# General Worker Method v1

## Preflight

1. Read Operating Model and list/search repository Issues.
2. Ignore pull requests and choose an executable Work Issue.
3. Resolve active Worker Method version unless already pinned.
4. Merge Method runtime requirements with Work Item-specific requirements.
5. Compare against tools/capabilities actually available.
6. Missing requirement → do not claim; update the item to `blocked` with a structured Manager escalation.

## Claim

For Issue #N:

1. Re-read the Issue body metadata.
2. Resolve the Worker Method active version.
3. Check `company/claims/issue-N.json`.
4. If a live lock exists, choose another Issue.
5. If an expired lock exists, delete it using its current SHA.
6. Attempt to create `company/claims/issue-N.json` with agent, runner, lease, and pinned Worker Method version.
7. Create succeeds → claim won.
8. Create reports that the path already exists → claim lost; choose another Issue.
9. After winning, update Issue metadata to `running` and record the pinned Worker Method version.

Heartbeat by fetching the lock with its SHA and extending `leaseExpiresAt`.

## Execute

Perform only the delegated work. Do not expand into Manager discovery.

For deliverables requiring approval, create a branch/PR and link it from the receipt. Otherwise direct commits are allowed when the Work Item permits them.

## Validate

Run the Work Item validation strategy using actual available capabilities. Never invent commands, evidence, or deployment verification.

## Complete

When acceptance criteria and validation pass:

1. update the Work Issue metadata with execution receipt, result summary, `finishedAt`, and `status: archived`,
2. close the GitHub Issue as completed,
3. delete the claim lock using its current SHA.

Use `review` only when implementation and validation are complete and only judgment remains.

## Problem

Unfinished + known compatible next route → update the Work Issue to `in_progress`.

Currently not executable → update it to `blocked` and add a structured escalation comment for Manager.

After the Issue transition is recorded, delete the claim lock.

Do not create a System Incident directly unless a Manager Method explicitly delegates that responsibility.
