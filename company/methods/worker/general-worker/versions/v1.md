# General Worker Method v1

## Preflight

1. Read Operating Model, Work Item, Worker Method.
2. Resolve active Worker Method version unless already pinned.
3. Merge Method runtime requirements with Work Item-specific requirements.
4. Compare against tools/capabilities actually available.
5. Missing requirement → do not claim; report capability problem to Manager and block the item.

## Claim

Fetch the Work Item with its current blob SHA. If claimable, current-SHA update:
- status → `running`
- pin `workerMethodVersion`
- set claim identity and lease
- record runtime availability

A conflict means state changed. Refetch; never force.

## Execute

Perform only the delegated work. Do not expand into Manager discovery.

For deliverables that require approval, create a branch/PR and link it from the receipt. Otherwise direct commits are allowed when the Work Item permits them.

## Validate

Run the Work Item validation strategy using actual available capabilities. Never invent a quality command or claim a deployment was verified when it was not.

## Complete

If acceptance + validation pass:
- status → `archived`
- clear claim
- set result summary and finishedAt
- save execution receipt with delivery status, artifacts, validation

Use `review` only when implementation and validation are complete and only judgment remains.

## Problem

If unfinished but a compatible next route exists → `in_progress`.

If currently not executable → `blocked` with structured escalation to Manager.

Do not create a System Incident directly unless an explicit Manager Method delegates that responsibility.
